# AI 想法图谱

> 我对 AI 的零散想法、查到的相关研究，以及想法之间的演化链 —— 做成一张打开就能逛的图谱。

**[打开在线图谱 →](https://ciyuankuayue.github.io/ai-ideas-hub/)**　不用注册，不用克隆，不用装任何东西。

---

## 为什么做这个

### 目的：想法不该只停在笔记里

我平时对 AI 有很多想法——关于检索、关于智能体、关于人和模型该怎么分工。它们大多零散地留在对话和笔记里，时间一长就互相覆盖，最后只剩下「我好像想过这个」的印象。

这个仓库是个容器：**每个想法是一个节点**，写清楚动机和我想解决的问题；查过的论文和项目挂在节点旁边；想法之间的启发与衍生关系用连线标出来。于是一条思路是怎么长出来的，能一眼看见。

### 初衷：先查证，再记录

记想法很容易变成自说自话。所以每个节点都留了「已查到的相关研究」——如果我以为的新方向其实几年前就有人做过，我宁愿在图谱上标出来，也不想反复重新发明它。

这张图同时也是一份诚实的记录：哪些想法被证伪了、哪些搁置了、哪些正在动手。状态是公开的，不修饰。

### 期盼：有人来把它拆开、接下去

一个人能想到的边界很窄。写在这里，是希望有人看到某个节点时想：

- **「这个我也想过，但角度不一样」** —— 补一个节点，用连线挂上去，链条就长了一节；
- **「这个方向其实已经有成熟工作了」** —— 往 `research` 里加一条链接，替我省掉一次试错；
- **「这个想法有问题」** —— 直接在 Issue 里说。被推翻的想法，比被忽略的想法有价值。

不需要是研究者，也不需要同意我。**留下一个反例、一条文献、一个更尖锐的问题，都算参与。**

## 这个仓库的用法

一句话：**数据即视图**。图谱不是手画的，是从一份 JSON 渲染出来的。改数据，图就变。

```
.
├── index.html                     # 交互视图入口
├── assets/
│   ├── style.css                  # 深色主题
│   └── app.js                     # 力导向图谱 + 卡片 + 搜索/筛选/详情（零依赖，无 CDN）
├── data/
│   └── ideas.json                 # 想法源数据 —— 唯一需要维护的文件
├── CONTRIBUTING.md                # 更细的字段说明与协作规范
└── .github/
    ├── ISSUE_TEMPLATE/propose-idea.yml   # 「提议新想法」表单
    └── PULL_REQUEST_TEMPLATE.md          # 提交 PR 时的检查清单
```

**只是想读**，不需要看代码：

1. 打开在线图谱，切到「卡片」视图通读一遍，知道现在有哪些想法；
2. 对某个节点好奇，点开看它的上下游逻辑链，顺着链条往上追或往下走；
3. 想知道某条思路有没有人做过，看节点里的「已查到的相关研究」；
4. 有话说，点「参与研究」开 Issue，或走下面的任意一种参与方式。

## 参与与扩展指南

按你愿意投入的时间选一条。**都不需要事先问我，也不用等授权。**

| 方式 | 你要做什么 | 适合 | 耗时 |
|---|---|---|---|
| **A. 开 Issue** | 提一个想法 / 补一条文献 / 指一个错 | 只想留一句话 | 1 分钟 |
| **B. 网页改数据** | 在 GitHub 网页上编辑 JSON 提 PR | 想让想法立刻出现在图谱上 | 5 分钟 |
| **C. clone 到本地** | 拉下来改，批量加节点或改视图 | 想长期参与、一次加多个 | 半小时起 |
| **D. 深化已有想法** | 给现有节点补研究、补问题、挂链条 | 不新增节点，只想把某条做实 | 10 分钟 |

### A. 最简：开一个 Issue（零门槛，最推荐给第一次来的人）

两种入口，效果一样：

- 在**在线图谱**里点开任意节点 → 点详情底部的「参与研究」，Issue 会自动带上节点 id 和标题；
- 或者直接在仓库点 **Issues → New issue**，选「提议新想法」表单，按提示填。

写什么都可以：一个新想法、一篇你想到的相关论文、一句「这个方向我试过，走不通，因为……」。我会把它整理成节点并回关 Issue。

### B. 零克隆：在网页上直接改数据（推荐）

想让自己的想法马上变成图谱上的一个点，走这条：

1. 打开 [`data/ideas.json`](data/ideas.json)，点右上角的铅笔图标进入编辑；
2. 在 `ideas` 数组里**复制一个现有节点**，改成你的内容（比从空白写容易）；
3. 至少填这几项：`id`（唯一，别和现有的重复）、`title`、`summary`、`thought`；
4. 拉到页面底部，写一句提交说明，选 **Create a new branch and open a pull request**，点提交；
5. 我合并后 GitHub Pages 会在一两分钟内自动重建，你的节点就出现在图上了。

一个最小可用节点长这样：

```json
{
  "id": "idea-004",
  "title": "想法标题",
  "tags": ["AI", "检索"],
  "status": "raw",
  "summary": "一句话说清这个想法",
  "thought": "你的原始想法：为什么会想到它、想解决什么问题",
  "research": [],
  "chain": { "inspiredBy": [], "leadsTo": [], "openQuestions": [] }
}
```

如果想让别人更容易接手，建议在节点里补一个 `proposal` 对象（核心假设 / 新颖性查重 / 可行性 / 路线图），比自由文本更容易被认领——结构见下方[字段速查](#字段速查)。

字段含义、状态枚举、连线规则见下面的[字段速查](#字段速查)和 [`CONTRIBUTING.md`](CONTRIBUTING.md)。

### C. 深入参与：clone 到本地

适合想批量加节点、或者想改前端视图的人：

```bash
git clone https://github.com/ciyuankuayue/ai-ideas-hub.git
cd ai-ideas-hub

# 本地预览：必须经静态服务器，直接双击 index.html 会被浏览器的 CORS 拦住
python -m http.server 8000
# 浏览器打开 http://localhost:8000
```

改完 `data/ideas.json`（或 `assets/` 下的样式与视图），提交到新分支，开 PR 说明改了什么。前端是零依赖的原生 JS + canvas，没有构建步骤，改完刷新就能看到效果。

### D. 不是加新想法，而是把已有的做实

这条常被忽略，但对我价值最大：

- **补研究**：给某个节点的 `research` 加一条 `{ title, url, note }`，`note` 写清它和这个想法是什么关系（支持 / 反驳 / 已经做出了类似的东西）；
- **补问题**：往 `openQuestions` 里加一个更尖锐的问题，比原想法更能推进讨论；
- **挂链条**：如果你有一个相关想法，不用单独发明，用 `inspiredBy` / `leadsTo` 把它接到现有节点上，图谱会显示两段思路的关系；
- **提反例**：在 Issue 里明确指出某个节点的假设不成立，我会把状态改成 `dormant` 并写明原因。

## 字段速查

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 唯一标识，形如 `idea-004`，一旦被其他节点引用就不要改 |
| `title` | 是 | 想法标题，一句话，尽量具体 |
| `tags` | 否 | 标签数组，用于筛选，如 `["AI", "检索"]` |
| `status` | 是 | 见下方状态枚举 |
| `summary` | 是 | 一句话摘要，图谱和卡片上显示 |
| `thought` | 是 | 原文：动机、想解决的问题、你的判断 |
| `proposal` | 否 | 可选「微型提案」：把想法拆成 4 项便于他人认领——`hypothesis`(核心假设) / `novelty`(新颖性·查重) / `feasibility`(可行性) / `roadmap`(路线图)。**填了更容易被认领** |
| `research` | 否 | 已查到的研究，元素为 `{ title, url, note }` |
| `chain.inspiredBy` | 否 | 上游：这个想法从哪些节点来的，填它们的 `id` |
| `chain.leadsTo` | 否 | 下游：这个想法催生了哪些节点，填它们的 `id` |
| `chain.openQuestions` | 否 | 开放问题数组，用来邀请别人参与 |

### 状态枚举

| 值 | 含义 |
|---|---|
| `raw` | 原始想法，还没细想 |
| `exploring` | 探索中 |
| `hasResearch` | 已查到相关研究 |
| `wip` | 正在动手做 |
| `dormant` | 暂时搁置（或被证伪） |

### 连线怎么生效

图上的线完全由引用自动生成，不需要手动画：

- `inspiredBy` → 从被引用的节点指向你（蓝色箭头）；
- `leadsTo` → 从你指向被衍生的节点（绿色箭头）；
- `research` → 连到论文 / 项目节点（紫色）。

只填你确定的关系，不确定就留空数组——留空不会报错，也不会画出奇怪的线。

## 与已有工作的区别

建这个仓库前，我先查证了类似的东西是否有人做过——这也正是本仓库「先查证再记录」的初衷。结论：图谱工具有人做，公开想法仓库有人做，但把两者用一套**带语义的 schema** 结合起来、并且让「已查研究」和「想法状态」成为一等公民的，是空的。

| 项目 | 它是什么 | 和我们像在哪 | 关键差别 |
|---|---|---|---|
| **Quartz** | Obsidian/Markdown → 静态站，自带交互图谱、反链、全文搜索 | 数据文件 + 前端渲染 + Pages 托管，技术路径几乎一样 | 关系是 wikilink（"提到"），没有方向性的 `inspiredBy`/`leadsTo`；没有专门的 `research` 字段，你的判断和别人论文混在一起；没有 `status` 生命周期 |
| **VLN-Research-Quest** | 公开研究想法清单，Markdown「微型提案」，fork+PR 认领 | 公开想法 + PR 参与 + 被认领 + 要求署名 | 没有图谱、没有想法间演化链、没有状态流转，浏览靠翻文件夹 |
| **rags-lab** | papers/frameworks/ideas/discussions 分层，用 PR 讨论代替 Issue | 公开想法 + 协作 | 无可视化 |
| **Open Ideas Hub** | 一个想法一个文件夹 + `idea.md`，PR 提交 | 公开想法 + PR | 无可视化 |
| **Foam / Obsidian Publish** | VS Code + GitHub 的笔记图谱 / 付费发布 | 笔记图谱 | 个人笔记工具，不邀请陌生人参与；关系仍是 wikilink |
| **project-graph / Ideon / IdeaMesh** | 图形化整理思路的桌面/画布工具 | 图谱形态 | "自己用"的工具，不是公开邀请协作的仓库 |

**为什么不直接用 Quartz**：如果目标只是"漂亮的笔记图谱"，Quartz 更省力。但本仓库的价值在 schema 不在渲染——`research` 把"我查过"和"别人结论"强制分开，`inspiredBy`/`leadsTo` 是语义化因果而非"提到"，`status` 让"哪些被证伪了"可见。这些 Quartz 都没有。选自写零依赖视图，是为了 schema 完全可控、fork 后零配置即可用。

**空位不等于需求**：也可能大多数人不需要"显式因果链"这种约束，写笔记时手一松就退化成 wikilink。这点我清楚，所以把约束写进 schema 和 README，靠约定守住。

## 几条约定

- **想法可以是粗糙的。** 半成品、直觉、还没验证的猜测都欢迎，标成 `raw` 就行。
- **引用必须带链接。** 说「有人做过」请给 URL，否则别人没法核查。
- **不确定的关系留空。** 宁可少一条线，不要凭印象连错。
- **讨论留在公开的地方。** 用 Issue 或 PR 评论，别用私信——后来的人也能看到这段推理。
- **不要写入个人隐私。** 真实姓名、邮箱、住址、公司内网链接这类信息不必出现在数据里；想署名用 GitHub 账号即可。
